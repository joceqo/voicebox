# MLX-specific dependencies (Apple Silicon only)
# These should only be installed on aarch64-apple-darwin platforms

mlx>=0.30.0

# miniaudio is a runtime dep of mlx-audio's STT path (mlx_audio.stt).
# mlx-audio itself is installed --no-deps (see comment below), so we
# must list miniaudio explicitly here or transcription fails on fresh
# M1 installs with `ModuleNotFoundError: miniaudio` (issue #505).
miniaudio>=1.59

# mistral-common[audio] is required by the Voxtral TTS engine: mlx-audio's
# Voxtral model loads a Mistral "tekken" tokenizer that lives in
# mistral_common.tokens, and the [audio] extra pulls in soundfile/soxr used
# by the audio path. Voxtral weights are CC BY-NC 4.0 (non-commercial).
mistral-common[audio]>=1.10.0

# NOTE: mlx-audio is intentionally not listed here. From 0.3.1 onward it
# declares `transformers==5.0.0rc3` / `>=5.0.0`, which conflicts with the
# `transformers<=4.57.6` cap in requirements.txt and breaks CI's clean
# resolver. The mlx-audio API surface we use (mlx_audio.tts.load,
# mlx_audio.stt.load) works fine on transformers 4.57.x in practice.
#
# mlx-lm is a runtime dep of the Voxtral TTS engine (its Mistral decoder
# reuses mlx_lm.models.llama / mlx_lm.models.cache). It must be installed
# --no-deps: a plain `pip install mlx-lm` drags transformers>=5 and
# huggingface_hub>=1 in, both of which break the transformers<=4.57.6 / hub<1
# pins the other engines rely on. mlx-lm's real runtime deps (mlx, numpy,
# pyyaml, jinja2, protobuf) are already present.
#   pip install --no-deps mlx-lm==0.31.3
#
# Install it via `pip install --no-deps mlx-audio==0.4.3` after this file
# (see .github/workflows/release.yml). 0.4.3+ is required for the Voxtral TTS
# model (mlx_audio.tts.models.voxtral_tts, added after 0.4.1). Most other
# mlx-audio runtime deps (huggingface_hub, librosa, mlx-lm, numba, numpy,
# protobuf, pyloudnorm, sounddevice, tqdm) are already in requirements.txt or
# pulled in by other engines.
